# Auto Commenter

Система для автоматического **комментирования постов в Telegram‑каналах** от имени вашего канала с возможностью:

- хранения истории комментариев в SQLite
- гибкой конфигурации каналов и шаблонов
- соблюдения лимитов по частоте и повтору шаблонов
- расширения за счёт миграций и вспомогательных скриптов

Структура проекта вдохновлена соседними сервисами для управления Telegram‑аккаунтами.

## ⚙️ Установка

1. Установите **Python 3.10+**.
2. Склонируйте репозиторий и установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создайте файл `.env` в корне проекта:
   ```ini
   TELEGRAM_API_ID=123456
   TELEGRAM_API_HASH=abcdef0123456789abcdef0123456789
   TELEGRAM_SESSION_NAME=auto_commenter
   AUTO_COMMENTER_DB_PATH=data/comments.db
   MIN_DAYS_BETWEEN_COMMENTS=7
   TEMPLATE_COOLDOWN_DAYS=45
   CHANNEL_CONFIG_PATH=config/channels.json
   ```
   > ⚠️ `.env` уже игнорируется `.gitignore`, не добавляйте его в репозиторий.
4. Скопируйте пример конфига каналов и заполните его:
   ```bash
   cp config/channels.example.json config/channels.json
   ```
   В файле укажите `source` (откуда ловим посты), `send_as` (канал, от имени которого отвечаем) и список шаблонов комментариев.
5. Проинициализируйте базу данных:
   ```bash
   python -m scripts.init_db
   ```

---
## 🚀 Запуск

1. Убедитесь, что все зависимости установлены и `.env` заполнен.
2. Запустите бота:
   ```bash
   python -m src.main
   ```
3. Приложение выведет список каналов, которые слушает, и будет автоматически оставлять комментарии согласно правилам:
   - Минимум `MIN_DAYS_BETWEEN_COMMENTS` дней между комментариями в одном канале
   - Не использовать один и тот же шаблон чаще, чем раз в `TEMPLATE_COOLDOWN_DAYS` дней

Вся история действий сохраняется в таблице `comment_log`, поэтому бот корректно возобновляет работу после перезапуска.

## 🧱 Миграции

Для изменения схемы БД добавляйте новые файлы `migrations/00X_description.sql`. Скрипт `python -m scripts.init_db` применит их последовательно. Это облегчает поддержку нескольких окружений и развёртывание.

---
## 🧰 Полезные советы

- Логи запуска записываются в консоль. При необходимости можно расширить проект отдельным логгером в `src/auto_commenter/utils/`.
- Для хранения чувствительных данных (API ID, HASH, путь к БД) используйте только `.env`.
- При масштабировании на несколько проектов достаточно добавить новые миграции и конфиги каналов.
